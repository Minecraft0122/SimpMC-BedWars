# 常见问题与排错

## 插件拒绝启动

确认三项：

1. 服务端确实是 Paper 1.21.11。
2. `java -version` 显示 Java 21 或更新兼容版本。
3. `plugins` 中没有重复的 SimpMC-BedWars JAR。

Spigot、Folia、旧世界格式和其他 Minecraft 版本会被主动拒绝。

## 配置解析错误

- 检查 YAML 缩进，只能使用空格。
- 检查列表前的 `-` 和字符串引号。
- 对比自动生成的 `.bak`。
- 不要手动修改 `config-version`。
- Material、Sound、Enchantment、PotionEffect 使用 Paper 1.21.11 名称。

## 控制台出现大量 `DEBUG:` 日志

确认 `plugins/SimpMC-BedWars/config.yml` 中为 `debug: false`，然后完整重启后端。`/bw start debug` 中的 `debug` 表示允许单队测试开局；2.10.35 起它不会再开启全局详细日志。竞技场和逐生成器初始化信息已经彻底移除，即使管理员主动开启详细日志也不会刷这些低价值内容。

## 已安装 Vault，但插件仍然没有经济功能

先根据控制台信息区分两种情况：

- `未检测到 Vault API`：Vault 没有成功加载、版本不兼容，或插件 JAR 放置错误。检查 `/plugins`、Vault 自身启动日志和依赖版本，然后完整重启。
- `已检测到 Vault API，但没有已注册的经济服务`：Vault 已经被识别，但没有经济插件向它注册服务。Vault 本身不保存余额，需要另装支持 Vault 的经济插件。

正确加载时会显示 `已接入 Vault 经济服务：服务名（提供插件：插件名）`。本插件会监听服务的延迟注册，因此经济插件稍晚启用时不需要再次重载 SimpMC-BedWars。不要使用 `/reload` 解决依赖顺序问题。

## `Missing message key ... zh_cn.v1.bak`

这是旧版本误加载语言迁移备份造成的。2.10.0 及之后严格只加载 `messages_<语言>.yml`。升级并完整重启即可，`.bak` 文件可以保留。

## 玩家加入时报位置数组越界

旧版大厅坐标字段数量不完整。当前版本会规范化旧坐标并备份配置。若仍出现，重新站在大厅执行 `/bw setLobby`，然后完整重启。

## 竞技场无法启用

按顺序检查：

- 世界文件夹名称全小写且存在。
- 至少两支队伍。
- 每队已设置 Color、Spawn、Bed、Shop、Upgrade。
- 等待点和观战点所在世界正确。
- `minPlayers` 至少为 2 且不超过地图总容量，`maxInTeam` 至少为 1，并且地图至少配置两支队伍。
- 控制台是否指出具体缺失路径。

## 自动找不到床

- 将队伍出生点设在本队床附近。
- 确认 `island-radius` 覆盖床但不会同时覆盖其他队床。
- 使用 `/bw setBed <队伍>` 手动设置。

## 出生点被遮挡

插件会在附近搜索安全位置并允许一格高空间趴下。如果仍失败，应在队伍出生点周围保留实体脚下的实心安全方块，并移除岩浆、火、仙人掌、岩浆块、细雪和滴水石。

## 游戏只有一支队伍

当前版本在总人数达到 `minPlayers` 后尝试分队，并强制至少两支非空队伍、每队不超过 `maxInTeam`。一个人数未超过容量的完整小队不会被拆成两队制造对手。若第三方附属插件取消全部 `TeamAssignEvent` 或使用错误的自定义分配器，开局会停止并在控制台打印警告。只有管理员明确执行 `/bw start debug` 时才允许单队测试。

## 火球飞不远或潜行没有加速

- 完整重启后检查 `config.yml`：默认应为 `fireball.speed-multiplier: 16`、`sneak-speed-multiplier: 1.5`。
- 普通初速度约为 1.6 格/tick；按住潜行键再右键发射时约为 2.4 格/tick，并伴随轻微反向后坐。
- 100–200 格是开阔且沿途区块已加载时的参考移动距离，不是硬性最远距离。方块、实体、世界边界、服务端视距和未加载区块都可能让火球提前停止。
- 插件不会为了火球强制加载远处区块，否则连续发射会造成额外主线程和内存压力。修改参数后不要使用 `/reload`，必须完整重启。

## 大厅玩家能修改物品或方块

- 当前版本会阻止大厅玩家点击、拖拽、合成、交换副手、使用和丢弃背包物品；Q、Ctrl+Q 以及管理员建造会话也不能绕过丢弃保护。
- 确认 `serverType` 是 MULTIARENA。
- 确认玩家所在世界就是 `/bw setLobby` 保存的大厅世界。
- 管理员若执行过 `/bw build`，再次执行退出建造会话。
- 完整重启，避免热重载留下旧监听器。

## 主大厅看不到玩家进入、退出或加入竞技场提示

2.10.37 修复了独立大厅世界在插件加载阶段尚未加载时，缓存大厅世界名为空的问题。确认 `lobbyLoc` 最后一个逗号后的字段是实际大厅世界文件夹名，并完整重启服务器。大厅进入/退出提示只对大厅玩家可见；竞技场加入提示只在目标竞技场处于等待或开局倒计时阶段发送，已开局后加入旁观不会广播。

## “回到主大厅”红床没有切换服务器

2.10.36 起必须先完整重启并重新进入大厅，让插件发放带有目标标记的红床；重启前已经留在背包中的旧物品没有此标记。2.10.46 起点击红床不会向玩家发送任何代理查询、节点名称、服务器列表、连接进度或失败诊断，而是立即静默发送 `Connect <lobbyServer>`。

如果点击后仍留在当前服务器，请由管理员检查：

- 玩家是否通过 BungeeCord/Velocity 的监听地址进入，而不是直连 BedWars 后端 Paper 端口。
- Velocity 的 `velocity.toml` 是否在 `[advanced]` 下设置 `bungee-plugin-message-channel = true`，修改后是否完整重启代理。
- 插件 `config.yml` 的 `lobbyServer` 是否与代理 `[servers]` 中的键名完全一致，例如 `hub`；不要填写地址、端口、MotD 或显示名称。
- 目标大厅后端是否在线，以及代理日志是否记录拒绝连接、转发配置错误或目标不存在。

可直接照抄的 Velocity/BungeeCord 配置见[安装文档](installation.md#bungee)。不要用 `/reload` 测试插件消息通道；应完整重启代理和后端。

## 死亡或复活异常

- 普通死亡：原地进入旁观模式。
- 虚空死亡：传送到队伍安全出生点。
- 最终死亡：留在观战状态。

## 竞技场重置时玩家被踢出

2.10.38 已删除 `You're not supposed to be here.` 重置踢人逻辑。倒计时到 0 后会先返回大厅，确认竞技场世界无人后才卸载；异步传送失败时每秒重试并保持世界加载。若地图一直不重置，检查控制台的大厅目标警告和 `lobbyLoc`，而不是强制卸载仍有玩家的世界。

## `Corrupt regionfile header` 或区块坐标不匹配

`Attempting to read chunk data ... but got chunk data for ... instead` 表示对应世界的 `.mca` 区域文件头已经损坏，不是普通 Java 插件异常。Paper 会先生成形如 `r.-1.-1.mca.<数字>.backup` 的备份，再尝试重建文件头；日志明确写着 `could not be recovered` 的区块只能重新生成或从已知完好的地图备份恢复。

若错误来自竞技场地图：先停止服务器并备份整个实例，再从完好原图替换日志点名的 `region/r.*.*.mca`。使用内部地图恢复器时还必须同步替换或删除 `plugins/SimpMC-BedWars/Cache/<竞技场>.zip` 中的损坏副本，否则每局重置都会再次还原坏文件。不要把 Paper 自动生成的 `.backup` 当作完整原图。当前版本在设置会话结束后会等待玩家离开、确认世界成功卸载，才异步压缩地图；若 60 秒内仍无法安全卸载，只记录错误并放弃本次压缩，不再读取仍加载的区域文件。

## 放置后方块暂时看不见

如果背包数量已经扣除、服务端实际也存在该方块，但客户端直到再次点击对应位置才显示，这是方块状态同步延迟，不是物品或方块被删除。2.10.45 起插件会把同一玩家同一 tick 的成功放置合并，在下一 tick 只向放置者批量重发服务端真实状态；该流程不会刷新整份背包。

若升级后仍频繁发生，应使用 spark 检查主线程卡顿来源，并确认客户端版本与代理协议转换插件兼容。额外同步只能修正画面，不能消除其他插件、世界保存或硬件造成的长时间停顿。

## TAB 玩家名或头顶名牌没有队伍颜色

- 先确认插件版本至少为 4.0.4，并在替换 JAR 后完整重启；不要使用 `/reload`。
- 游戏内 TAB 与头顶名牌使用两条独立链路：TAB 直接向每个查看者发送“前缀 + 明确队伍色玩家名 + 后缀”的 PlayerInfo 显示名，头顶名牌由该查看者的 scoreboard team 负责。关闭完整 TAB 前后缀不会关闭核心队伍色。
- 进入服务器时，插件会等待新玩家的 `ADD_PLAYER` 条目已经广播后再更新已有观察者；首次世界加载时若大厅 TAB 尚未建立，也会立即补建。跨世界、加入竞技场、离场及 `showPlayer` 重建条目后均会重放对应状态。若刚进服仍长期显示原版 TAB，请先确认服务端实际加载的是 4.0.4 JAR，而不是只替换了未重启的文件。
- 若只有头顶颜色失效，检查是否有其他计分板、Nametag 或大厅插件在 BedWars 之后替换玩家的 scoreboard；若只有 TAB 失效，检查启动日志是否出现“无法初始化 Paper 1.21.11 TAB 数据包支持”，以及其他插件是否持续发送 PlayerInfo 显示名更新。4.0.4 的启动检查会实际构造并回读队伍色 PlayerInfo 数据包；插件仍会在相关事件发生时即时修复，并按配置周期批量自愈后续覆盖。
- 在只安装 SimpMC-BedWars 的 Paper 1.21.11 测试服复现一次，可区分插件冲突和本插件问题。提交报告时附上 `plugins` 列表、相关语言文件的 `formatting.tab-list` 配置及游戏状态。

提交问题时附上完整异常、发生时玩家状态、竞技场配置以及 mclo.gs 链接。

## 性能排查

- 使用 SSD 存放世界和插件目录。
- 保持 Paper 优化及 `stack-items` 开启。
- 不要过度降低生成间隔或提高地面资源上限。
- 避免极短的计分板/TAB 刷新周期。
- 使用 Paper timings 或 spark 定位实际热点，不要只根据单次卡顿猜测。
