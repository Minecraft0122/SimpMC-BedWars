# 安全审计与部署加固

本页记录 `2.10.3` 的代码级安全审计。审计范围包括玩家事件边界、地图方块所有权、文件路径、地图压缩包、数据库查询和大厅套接字。它不能替代 Paper、Java、操作系统及全部第三方插件的独立安全审计。

## 本次已经修复

### 高：玩家方块幽灵标记可破坏地图

旧实现使用允许重复的 `LinkedList<Vector>` 保存坐标，并线性扫描判断方块。TNT 自动点燃、爆炸、燃烧或方块褪色后，坐标没有全部删除；同一位置重复放置还会生成多条记录。普通破坏只删除一条，残留坐标会把后来出现的地图原生方块误判为玩家方块。

`2.10.3` 改为竞技场独立的唯一坐标索引：

- 添加、删除和判断的平均复杂度由 O(n) 降为 O(1)。
- 同一坐标最多只有一个所有权标记。
- 只在 `BlockPlaceEvent` 最终未取消时记录，并支持多方块放置。
- 爆炸、燃烧、褪色和重力方块移动会同步所有权。
- 自动点燃的 TNT 和被取消的弹射塔物品不会留下标记。
- 地图禁止破坏时同时禁止活塞移动，避免把原生方块移动到已有标记上。

旧 API `IArena#getPlaced()` 现在返回脱离内部状态的兼容快照并标记为弃用。附属插件应使用 `addPlacedBlock`、`removePlacedBlock` 和新的 `getPlacedBlocksSnapshot()`。

### 高：未加入游戏的玩家可操作竞技场世界

如果其他传送插件把玩家直接送入正在运行的竞技场世界，旧逻辑只按 `Arena#getArenaByPlayer` 判断身份；未注册玩家可能绕过方块放置、破坏、桶、PVP 和资源拾取限制。

现在会拒绝未注册玩家传送进入已启用的竞技场，并在放置、破坏、桶、伤害和拾取事件上再次校验“目标世界竞技场”与“玩家所属竞技场”必须一致。正常加入、重连和员工旁观会先注册再传送，不受影响。

### 高：地图 ZIP 路径穿越

旧解压逻辑直接拼接 ZIP 条目名。包含 `../` 或绝对路径的恶意备份能够把文件写出目标世界目录。

现在解压前先规范化并检查全部条目；只要任意条目越界，整个压缩包会在写入任何文件之前被拒绝。文件流和 ZIP 句柄也改为自动关闭。

### 中：竞技场世界名可形成路径穿越

设置、克隆、删除和分组命令过去只排除 `+`，没有统一拒绝 `/`、`\\`、`..`、盘符和控制字符。虽然这些命令需要管理权限，但错误授权或附属插件调用恢复 API 时可能操作预期目录之外的路径。

现在命令入口和内部地图恢复适配器都会验证世界名，并保留中文世界名、下划线和连字符等正常用法。

### 中：大厅套接字可被畸形数据拖垮

大厅连接过去使用无长度上限的 `Scanner`，缺少字段或非法 UUID 也可能让读取任务异常退出。现在单条消息限制为 64 KiB，统一使用 UTF-8，校验消息字段和 UUID，并在错误时关闭失效连接。

## 仍需注意的边界

### 大厅套接字仍没有对端认证和传输加密

竞技场服只会主动连接 `config.yml` 中配置的大厅地址，但协议本身没有共享密钥、签名或 TLS。不要把大厅端口暴露到公网；应使用内网、防火墙或受保护的隧道，只允许已知竞技场服务器访问。未来协议升级应增加版本号、时间戳、随机数和 HMAC，并预留密钥轮换。

### ZIP 恢复没有设置统一解压容量上限

路径穿越已经被拒绝，但为了支持不同体积的地图，当前没有硬编码压缩后/解压后比例和总字节上限。不要把来源不可信的 ZIP 放入插件备份目录；同时应监控磁盘剩余空间，并由运维层限制服务端账户可用磁盘配额。

### 数据库默认配置不是生产安全配置

数据库默认关闭，示例密码只用于提示配置结构。启用远程 MySQL 时必须创建最小权限专用账户、使用强密码、限制来源地址，并在数据库支持时开启 TLS。不要把真实密码提交到 Git。

### 聊天仍使用旧异步 Bukkit 事件

`AsyncPlayerChatEvent` 中会读取部分竞技场和玩家状态。2.10.28 修复了 `!消息` 入口未检查 `bw.shout` 的直接权限绕过，并与 `/shout` 共用权限门；异步读取 Bukkit 状态的线程安全与兼容性风险仍需后续迁移到 Paper Adventure 聊天事件或只读快照。

### 配置文件属于受信任输入

大厅物品和部分奖励支持执行管理员配置的命令。获得插件数据目录写权限的人等同于获得服务器管理权限。生产环境应限制系统账户和面板用户权限，并对配置变更进行版本控制和审计。

## GitHub 安全能力

本次检查时，仓库的 Dependabot alerts 处于关闭状态，Code Scanning 也没有分析结果。因此本页不宣称已经排除第三方依赖 CVE。建议仓库管理员在 GitHub 的 Security 设置中启用 Dependabot alerts、Dependabot security updates 和 CodeQL，并定期检查 Paper、数据库驱动及打包依赖。

## 建议的验证场景

1. 在同一坐标反复放置、爆炸、再放置和破坏，确认标记数量始终为 0 或 1。
2. 用 TNT 炸掉玩家方块后，确认其下方地图方块不能继续破坏。
3. 测试沙子或沙砾下落后仍可破坏，但地图原生重力方块不会被误标记。
4. 使用其他传送插件尝试进入运行中的竞技场，确认传送被取消。
5. 构造含 `../outside.txt` 的地图压缩包，确认恢复失败且目标目录内也没有部分解压文件。
6. 向大厅套接字发送缺字段、非法 UUID 和超过 64 KiB 的消息，确认连接被拒绝且主线程不受影响。
